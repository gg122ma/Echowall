# EchoWall — Website Segment: Final Executable Script

InnoSTEM 2026 · Website demonstration segment only · Hard cap 2:15 · Target cut 2:05–2:12
No Admin. No Moderation Dashboard. No Register/Profile. Every beat ends on a real result.

Full rationale, source audit, and risk detail: `SCRIPT_RESEARCH_CLAUDE.md` (same folder). This
file is the shooting/editing script only.

## C. Final Story Structure

```
[ Idea segment — already fixed, ends on the Echo Map ]
        ↓ (direct continuation, no new title card)
Scene 1   Echo Map → Post Directly → enter the place's own wall
        ↓ (hard cut on page navigation)
Scene 2   Building Wall → Leave a Note with a photo → real vote
        ↓ (Sticky Match Cut — same category color + same shape)
Scene 3   All KM Students → Question ("...SM015...") → Comment → Marked Solved
        ↓ (SM015 text match cut)
Scene 4   Echo Library → search/filter SM015 → real PDF → matching Answer Scheme
        ↓ (push-in disguise cut)
Scene 5   Ask Echo → recommended question → instant real answer
        ↓ (panel slide / language panes enter)
Scene 6   English / Bahasa Melayu / 中文 shown side by side
        ↓ (elements converge into the EchoWall mark)
[ Impact segment — already fixed, picks up from here ]
```

One continuous idea across all 6 scenes: **a place → a person's note → a wider community →
structured knowledge → an instant answer → in three languages.** Not a feature list — one
student's path through the product.

between actions, never hovering a random button.

## Full English Voice-over (recording script)

> EchoWall begins on the map — where the problem actually happens.
> A student can post directly onto a real place — choose how the note looks — and step straight
> into that place's own wall.
> Inside the wall, students leave real experiences — with a photo, a category, a shape of their
> own — and react to what others already shared.
> Beyond one building, All KM Students connects the whole campus. A real question gets a real
> answer — and once it's resolved, it's marked solved for the next student who asks.
> That same subject code leads straight into Echo Library — search, filter, and open a real
> past-year paper, with its answer scheme right beside it.
> And when a quick question comes up, Ask Echo answers instantly, using the same campus knowledge.
> All of this works in English, Bahasa Melayu, and Chinese.
> One place. One question. One resource. EchoWall turns scattered campus knowledge into something
> every student can actually use.

**Word count: 163 words.** At a natural, unhurried competition-video pace (~2.2–2.5 words/sec),
that's roughly **65–74 seconds of actual speech inside a 129-second segment** — matching the
"leave real silence for match cuts and UI motion to do the work" principle carried forward from
the recording manual. Three transitions (Shot 04→05 boundary is spoken through; Shots 06→07,
08→09, and part of 10→11 are deliberately silent) are the quiet beats; do not add filler VO to
them.

## Recording Notes (must-read before shooting — full detail in `SCRIPT_RESEARCH_CLAUDE.md`)

1. **Never show Admin or Moderation.** Zero seconds, zero mention.
2. **Never show Register/Create Account/Profile.** Start every take already signed in.
3. Use a **normal test account**, not a moderator/admin account, if it's important that "Mark
   Solved" reads as author-driven rather than staff-driven — otherwise a moderator account also
   works but the VO already avoids over-claiming who can resolve a question.
4. **Core place: Pustaka (Perpustakaan). Core subject code: SM015.** Both are real, verified,
   camera-safe. Do not substitute other buildings/subjects without re-verifying they have real
   content the same day.
5. **Map → Building Wall is a real page reload** (`map.html` → `index.html`). Cut on it; don't try
   to animate across it.
6. **Building display counts (e.g. "43 notes") are static and will not increment on camera.**
   Never imply otherwise in a shot or VO line.
7. **Building notes have no comments — ever, by design.** Don't stage a comment attempt there.
8. Ask Echo's **recommended chip** path is the verified-stable one; treat a typed custom question
   as a bonus take, not the primary plan.
9. Every scene must end holding on a **real result** for at least ~1 second before cutting —
   marker, note, vote count, comment, Solved badge, filtered list, open PDF, Ask Echo answer.
10. Total segment ceiling is **2:15**; this script targets **2:09**, leaving margin — if any shot
    runs long in the edit, trim silent hold time first, not the result beats.

**Final self-check before locking the cut** (re-run against the live site, not from memory): walk
this exact shot list in a real browser end to end — does every click still navigate correctly, does
every result still render, is any state now empty/404/Coming Soon? If any shot no longer matches
reality, **fix the script, not the website.**
